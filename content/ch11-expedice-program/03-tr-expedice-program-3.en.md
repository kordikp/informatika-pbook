**🔍 Analysis** · step 3 of 5 · [Twelve stars](#expedice-program-en)

**Git** is a program that remembers every version of the code. Each save is called a **commit** and has a short message for people: what changed and why.

1. Open [Learn Git Branching](https://learngitbranching.js.org/). It’s a game in the browser, no account, in English. Go through the first four levels: commit, branches, merge and rebase. The circles are commits; the arrows point to the previous version.
2. This game is itself an open-source project. Open its code on [GitHub](https://github.com/pcottle/learnGitBranching). You can read it without an account.
3. Click the number of commits (the clock icon by the list of files). You can see the project’s history.

Answer for yourself:
- How many commits does the project have, and roughly when was the first one made?
- Find three commit messages you understand and one you don’t. Why don’t you understand that one?
- Find a commit that fixes a bug (look for the words “fix”, “bug”). Can you tell from the message **what** bug it was?
- What would happen if every message just said “changes”?

Finally, write three rules for a good commit message. To check: a good message is short, starts with **what** the change does, and lets you tell **why** it was made. You’ll use your rules in the last step.
