A friend cannot open the index.html file on your computer. For anyone to see the website, it has to move to a computer that never sleeps.

That computer is a **server**: it **provides a service** to others; here it sends the files of your website to anyone who asks for them. Space on a server is called **hosting**. For a school website it is free: you upload a folder to GitHub Pages or Netlify and a minute later you have an address like *our-club.netlify.app*.

Hosting is the **cloud**: your website runs on **someone else’s computer** in some company’s data centre. That has **advantages**: the server is on non-stop, it can handle a thousand visits at once and the company takes care of the updates. And it brings **dependencies**: when the company shuts the service down, raises the price or blocks your account, the website disappears. So keep the files of your website on your own computer too. **A backup in another place** is your insurance.

A **domain** is a name people can remember:

| | Hosting | Domain |
|---|---|---|
| What it is | the place where the website runs | the name that points to the website |
| Example | GitHub Pages, Netlify | ourclub.org |
| To start with | free | a subdomain for free, your own domain for a few euros a year |

The domain points to the IP address of the server. When you move to another hosting service, you just redirect it. The name stays, the server changes.

And where does the data centre stand? In some **country**, and that country’s laws apply there. When the website collects names and e-mails, for example through a sign-up form for an event, that data is stored there too. For services in the **EU**, the **GDPR** applies, and it sets out what they may do with personal data.

**Try it!** Type the domain of your school’s website into an “IP lookup” tool. Which company owns the server the website runs on, and which country is it in?
